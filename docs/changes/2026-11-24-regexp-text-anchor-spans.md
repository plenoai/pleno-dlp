Extend the #1034 candidate-span narrowing to patterns containing text anchors (`\A`, `^`/`$` without `(?m)`, `\z`) (#1037). Every span edge inside the input lies at least `utf8.UTFMax` bytes beyond what the anchor's bounds let any match reach, so a match found in a span can never start or end on an interior edge, and a text anchor fires only where the span edge is the input edge, exactly as in a whole-input search. `TestAnchorNarrowingMatchesStd` now also places generated matches at the start and end of the input, and `FuzzAnchorNarrowing` covers `$`, `^` and `\A…\z` patterns. croc/django/rails findings are byte-identical in git and filesystem modes. The measured CPU gain is within noise: a rails single-thread profile shows regexp work under 4% of samples, so tightening generic password/secret spans was not pursued; the remaining git CPU gap is in scheduler wakeups (`pthread_cond_signal`/`wait`, `kevent`).
