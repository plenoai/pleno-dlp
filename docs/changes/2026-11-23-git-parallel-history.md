Owners: connector-engineer, core-engineer, qa

`scan git` renders large histories (≥ 200 commits) through parallel `git log --no-walk=unsorted --diff-filter=d` shards over contiguous slices of the `rev-list` order instead of one serial `git log -p`; the merge pass is fed from `rev-list --parents`, and a new optional `sources.InlineScanner` lets the shards hand chunks to the engine in batches instead of one contended channel send each. Chunks carry `GitMeta.Ordinal` (oldest-first position; also set on the single-stream and offline walks), and the cross-commit dedup keeps the lowest ordinal and breaks same-commit ties by line, offset, Verifier backing, then detector type, so the reported introducing commit is deterministic (it previously varied run to run). Binary-patch classification is memoized per blob id, raw type-change (`T`) records now reserve both diff headers so later binary patches in the commit keep their own path (previously dropped or double-scanned), and local git/filesystem scans default `--concurrency` to one worker per CPU (minimum 8). rails full history 21.5 s → 4.6 s, django 18.9 s → 3.7 s with identical chunk and secret sets.
