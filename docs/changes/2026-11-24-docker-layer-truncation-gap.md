A corrupt or truncated docker image layer tar no longer stops silently. `pkg/sources/dockerimage` now emits the unparsed remainder (the failing header plus the rest of the layer stream) as one raw `(corrupt layer remainder)` chunk, or the partial body of a truncated entry, consistent with the #970 raw fallback; records a `FailureSource` coverage gap per layer through `engine.DegradedError`; and keeps that layer out of the incremental state so the next run rescans it. A layer that cannot be opened is a per-layer gap instead of aborting the whole image. An audit of the other source stream readers (GCS iterator, git/GitHub line scanners) found no other silent-stop paths. The e2e suite has no registry or daemon fixture, so unit tests with truncated uncompressed layers cover the change (#975).
