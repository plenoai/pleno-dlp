PDF Type0 fonts encoded with a predefined CJK CMap other than Identity and without `/ToUnicode` now decode to text (#946). Legacy CMaps (90ms-RKSJ-H/V, EUC-H, GBK-EUC-H, B5pc-H, HKscs-B5-H, KSCms-UHC-H, and the other 50 cid2code columns) go code → CID → Unicode through `<ordering>-cmaps.bin` tables that `scripts/gencidmap` inverts from the same pinned adobe-type-tools commit and digests (regeneration is byte-identical; column index in the generated `pdfcmapnames_gen.go`); a `-V` CMap is the `-H` table overridden by vertical-only codes. Unicode CMaps (`Uni*-UCS2/UTF16/UTF8/UTF32`) decode their codes directly. The CID → Unicode tables now fall back to the UCS2 columns, so half-width CIDs (Japan1 231–632, e.g. CID 264 = `A`) that have no UTF32 value decode instead of being dropped. Release binary grows by 68,752 bytes (darwin/arm64, +0.07%).
