Owners: detector-engineer, core-engineer, qa

Narrow every detector and format regexp to candidate spans before Go's regexp engine runs (#1034). At compile time `detectors.Regexp` and `Format` derive an anchor from the pattern's syntax tree: a literal set every match must contain, plus per-side bounds (byte counts, byte-class walks, alternatives) on how far a match extends from it; patterns without one fall back to the class run every byte of a match must lie in. Each window is then searched only on the merged spans around anchor occurrences, widened by `utf8.UTFMax` to rune starts so `\b`, `(?m)^`/`$` and rune decoding see the whole-input context; patterns with `\A`/`\z`, inputs with U+017F/U+212A for case-folded anchors, and spans covering more than 3/4 of the input take the whole-input path. Results are exactly the standard library's: `TestAnchorNarrowingMatchesStd` compares 14 method families on 946 anchored patterns, `FuzzAnchorNarrowing` fuzzes extent kinds against `regexp`, and croc/django/rails findings are identical in filesystem and git modes. Single-thread in-memory engine CPU drops 37–40% on django, 25–29% on rails, and 22–34% on croc.
