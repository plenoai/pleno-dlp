Owners: core-engineer, connector-engineer, qa

In-process history rendering (`PLENO_DLP_GIT_PATCH_RENDER=inprocess`, and the default for histories up to 20k commits) now walks the selected commits newest first from parallel `git log --raw` segments and deals small batches of consecutive commits to the workers, instead of giving each worker a distant contiguous slice. Packs delta older blob versions against newer ones, so every worker reads from the same era and the shared object store resolves nearly every blob as a cache hit or one delta. The object store resolves chains iteratively into reference-counted, recycled buffers held in an exact lock-striped LRU, caches every resolved version, returns blobs zero-copy to the renderer, and inflates with klauspost's zlib. Django: 31.9 CPU-s against 41.3 for `git log -p` and 48 for the previous in-process renderer, with identical finding sets on croc, django, and rails. `PLENO_DLP_GIT_SYNTH_STREAM=0` restores the sharded renderer. Part of #1019.
