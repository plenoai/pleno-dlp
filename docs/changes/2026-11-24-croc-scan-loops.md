Cut per-byte scan work in the detection and diff hot loops: the regexp prefilter tests ASCII eight bytes per load and finds byte-class runs by striding `min` bytes; Aho-Corasick checks one precomputed first-output entry per byte instead of walking `patternsAt`/`dictLink`; base64 runs are probed every `minBase64Run` bytes; ASCII lower-casing, xdiff record splitting, the zai `hexRunBeforeDot` prefilter and the pgpass line walk use word-at-a-time or vectorized searches. Each rewrite is pinned to its linear definition by a randomized equivalence test. On a 30-CPU host (hyperfine medians, wall s / CPU-s), croc git goes from 0.255/1.657 to 0.218/1.346 against kingfisher's 0.295/1.127 (1.19x); django git is 1.06x and rails git 1.14x, and filesystem CPU drops 12-18%. Finding sets are identical on all three repositories. Darwin pprof assigns about a third of samples to `runtime.madvise`, but `sys` time is only 0.06 s at one P; an xctrace Time Profiler run shows these samples are a SIGPROF attribution artifact, so #1044's fresh-heap hypothesis was not the cost (#1044, #1018).
