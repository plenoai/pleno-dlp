Buffered raw-variant findings now resolve `Raw` inside the vicinity window the detector actually matched, so a value repeated earlier in the chunk (e.g. in a doc comment) is attributed to the matching line; the offset feeds line resolution, `RawSpan`, and inline-pragma lookup. Diff-backed findings (protect, agent hooks) still fan out across files so an allowed fixture cannot suppress the same value elsewhere (#502), but an occurrence other than the matched one is reported only when the detector, re-run offline on that occurrence's line, reports the same value again (falling back to the earliest located occurrence); a common Go keyword value no longer fans out to every added line, which cut a whole-repo staged `protect` from ~124k to under 200 findings (#874). `APIKeyAssignment` and `HardcodedPassword` no longer read a value across a newline after the mapping separator (Go switch case labels named after the detector type), nor take an escaped string-literal fragment such as a leading backslash-n as a value, `APIKeyAssignment` drops unquoted Go code (reserved words, calls, identifier references such as a struct field set from a same-named variable), and `JSONConfigSecret` drops PascalCase type-name keys mapped to kebab-case status tokens (the detector-name to revoke-status table in the CLI tests). The repo-root `.pleno-allow.json` entries that only worked around these false positives (APIKeyAssignment and HardcodedPassword keyword values, the JSONConfigSecret revoke-status literal, and the MySQL/Redis fan-out entries) are removed (#886).
