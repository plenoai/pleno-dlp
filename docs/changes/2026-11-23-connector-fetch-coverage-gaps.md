Per-item connector fetch failures are coverage gaps instead of silent zero findings (#882). Slack file downloads (including the cross-origin refusals from #881), `files.info` lookups, thread replies, and unreadable channels are recorded as `engine.ScanFailure` and the scan returns `engine.DegradedError`, so `--fail-on-coverage` sees them. The same fix applies to Bitbucket (file fetch, per-repo), GitLab (blob fetch, per-project, MR comments), and Redash (per-query; sink errors now propagate instead of being dropped per row) through the shared `pkg/connectors/coverage_gaps.go` collector. Failed items stay out of the incremental checkpoint so the next run retries them, Slack and Redash fingerprints fail rather than hash a partial view, and oversize bodies remain a `--max-bytes` policy skip.
