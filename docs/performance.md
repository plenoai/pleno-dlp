# Local scanner performance contract

`make bench-performance` compares pleno-dlp with checksum-pinned TruffleHog
3.97.5, Gitleaks 8.30.1, and Betterleaks 1.8.1. Every workload must meet **both**
wall-time and peak-RSS budgets:

```text
pleno-dlp median <= 1.20 * min(competitor medians)
```

The minimum is computed separately for each metric. This implies the same
upper bound against every competitor. Faster scans and lower memory use pass;
the target does not require slowing down to stay within a symmetric band.
A finite matrix cannot establish performance on every possible input or machine.
No universal parity claim is made.

## Coverage and input shapes

The previous gate selected only one primary metric for each of five workloads.
It omitted Betterleaks and left secondary memory regressions outside acceptance.
The current matrix keeps those workloads and adds process startup, short files,
thousands of small files, deep paths, long lines, a 64 MiB file, minified and
nested JSON, overlapping keywords, malformed token prefixes, dense findings,
repeated credentials, window boundaries, UTF-8/UTF-16, CRLF, encoding alignment,
and ZIP/GZIP/TAR with nested and numerous archive members.

Each scan must find the complete set of deterministic synthetic GitHub tokens.
A missing or unexpected token, invalid JSON, scan error, timeout, incomplete
sample set, or missing competitor prevents that workload from passing. A fast
scanner that skips the input does not establish parity. Costs from completed
scans are retained even if their coverage check fails; the workload's `errors`
field distinguishes such invalid comparisons from valid performance results.

Canary checks establish unique-token coverage, not occurrence-level recall or
catalog equivalence. Repeated-token workloads exercise scanner cost under each
tool's deduplication policy; their finding counts need not match. Existing
labelled recall, detector, engine, source, and CLI tests remain separate gates.
With `--baseline-bin`, pleno-dlp's complete finding signatures must also match
its baseline, including source metadata and verdicts. Intentional coverage fixes
can differ from a baseline that missed a token and must be reviewed separately.

## Measurement

Each invocation scans identical generated bytes with its complete default
secret rule set. Network verification and PII are disabled. The comparison sets
one decoding layer and archive depth three; source-specific binary handling
remains visible through canary checks. pleno-dlp explicitly allows files up to
128 MiB and disables default path exclusions so large and minified inputs are
actually scanned. Tool configuration environment variables are removed and the
working directory is the generated fixture root.

Two warmups precede seven measured runs. Starting order rotates each round.
GOMAXPROCS equals the requested concurrency; pleno-dlp and TruffleHog receive
that worker count, while Gitleaks and Betterleaks keep their own worker policy.
Scheduled/manual CI runs separate jobs for concurrency one and eight.

Wall time includes startup and JSON output capture. `/usr/bin/time` supplies
peak RSS (Darwin bytes; Linux KiB converted to bytes). A timeout terminates the
whole process group, including the scanner beneath `time`. Results are saved
after each workload so later failures do not discard completed measurements.
Reports include tool versions, binary and harness hashes, exact commands,
fixture inventories and hashes, raw samples, coverage failures and both metric
ratios. `suite_complete` remains false for a partial selection or interrupted run.

Run performance measurements without competing builds, tests, or scanners.
Desktop contention invalidates acceptance timing; use an isolated CI runner
when the local machine is busy. Warm caches, different detector catalogs,
platforms, compiler versions, and archive/decoder semantics limit inference.

## Reproduction

```sh
make bench-performance
make bench-performance BENCH_PERFORMANCE_ARGS='--concurrency 1 --out bench/results/performance-1.json'
# Diagnostic subset; it does not establish complete-suite acceptance.
make bench-performance BENCH_PERFORMANCE_ARGS='--tasks keyword-storm percent-boundaries --runs 3 --warmups 1'
```

CI retains separate JSON artifacts for both concurrency settings and fails
when a required comparison is invalid or either budget exceeds 20%.

## Historical evidence

The [2026-09-21 five-workload report](../bench/performance/results-2026-09-21.json)
compared baseline `d7ef52429f78b93837607cce3b445bdd7ec33cdc` against TruffleHog
3.96.0 and Gitleaks 8.30.1 on an Apple M3. Its five selected primary metrics
passed, but sparse-text and keyword RSS were 120.44 and 146.78 MiB versus
Gitleaks' 79.39 and 112.56 MiB. That historical result does not satisfy the
current contract. Expanded-matrix acceptance and release verification remain
outstanding until a complete valid report passes both metrics for every case.
