Use this file to reproduce the methodology, not as a current performance
claim.

## Methodology

- Each tool was invoked once per measurement under `hyperfine
  --warmup 3 --runs 20 --ignore-failure`. The 3 warmup runs prime
  the filesystem cache and the macOS Gatekeeper / DTrace path-cache
  for the binary; the 20 timed runs are interleaved across tools so
  no single tool sees a consecutive thermal advantage.
- Verification (`--verify` for pleno-dlp, default-on for trufflehog)
  was **disabled** on every tool so that the measurement reflects
  engine cost, not upstream API roundtrip latency. Each tool's
  exit code was ignored because pleno-dlp and gitleaks return
  non-zero whenever findings exist.
- Each invocation redirects stdout to `/dev/null` so I/O cost does
  not pollute the measurement; both tools were configured to emit
  JSON to stdout.
- Reported statistics are computed from the 20 raw wall-clock
  samples hyperfine exports to JSON. Mean ± SD is **not** the
  primary statistic; medians are reported with a non-parametric
  bootstrap 95 % CI (B = 10 000, seed = 42).
- Pairwise comparisons use Welch's *t*-test (unequal variances)
  with Bonferroni correction for the three pairs (α' = 0.05/3 ≈
  0.0167). Cohen's *d* is the effect-size measure on the same
  pair.

## Threats to validity

1. **Detector-set parity.** pleno-dlp registered 607 detectors at
   capture time; current builds may differ. The compared tools also ship
   different rule sets:
   trufflehog ~800, gitleaks ~160. Wall-clock comparisons reflect
   "scan throughput at each tool's captured rule set,"
   not a controlled per-rule measurement. A like-for-like
   per-detector benchmark would require restricting each tool to a
   common rule subset; none of the three exposes the same set.
2. **macOS scheduling noise.** Workload D's wide 95 % CI for both
   Go tools (pleno-dlp σ ≈ 750 ms around a 1.3 s median) is
   consistent with macOS asymmetric P/E core scheduling — work can
   land on an E-core mid-run. Linux with `cpupower frequency-set
   -g performance` and `taskset -c 0-3` would tighten the CI.
3. **Filesystem cache state.** `--warmup 3` warms the page cache;
   results therefore reflect hot-cache scans. Cold-cache numbers
   would add ~50-150 ms of `read()` latency uniformly across all
   tools and is unlikely to change pairwise ordering.
4. **Bonferroni is conservative.** The only borderline comparison is
   pleno-dlp vs trufflehog on Workload D.
5. **Single hardware platform.** All measurements are on a single
   Apple M3 MacBook. Behaviour on x86-64 servers, on Linux with a
   different scheduler, or under containers with cgroup CPU caps
   may differ. We do not extrapolate beyond this configuration.
6. **Single corpus per workload class.** Workload D is dominated
   by Go source. Code in other languages with different keyword
   densities (Python config-heavy, Rust trait-heavy) would
   redistribute detector-dispatch cost.

## Reproducing

```sh
# --- Corpus B: 9.6 MiB synthetic logs, 0 secrets ---
mkdir -p /tmp/dlp-bench/corpus-b
for i in $(seq 1 200); do
  cat > "/tmp/dlp-bench/corpus-b/log_${i}.txt" <<'EOF'
2026-05-12T10:00:00Z INFO request=GET /healthz status=200 latency_ms=1.2
2026-05-12T10:00:01Z INFO request=GET /api/v1/users status=200 latency_ms=12.4
2026-05-12T10:00:02Z WARN slow query=select * from orders took=812ms
EOF
  for _ in $(seq 1 60); do
    cat "/tmp/dlp-bench/corpus-b/log_${i}.txt" >> "/tmp/dlp-bench/corpus-b/log_${i}.txt.tmp"
  done
  mv "/tmp/dlp-bench/corpus-b/log_${i}.txt.tmp" "/tmp/dlp-bench/corpus-b/log_${i}.txt"
done
# Verify SHA-256 (tar -cf - corpus-b | shasum -a 256):
#   33fc220a85858b1a5fd6f2364450a5b9cc5321e1ebb3739375fb049d5c433742

# --- Corpus D: 7.9 MiB real OSS ---
cp -R "$(go env GOMODCACHE)/github.com/go-git/go-git/v5@v5.19.0" /tmp/dlp-bench/corpus-d
cp -R "$(go env GOMODCACHE)/github.com/spf13/cobra@v1.8.1"        /tmp/dlp-bench/corpus-d/cobra
cp -R "$(go env GOMODCACHE)/github.com/aws/aws-sdk-go-v2@v1.41.7" /tmp/dlp-bench/corpus-d/aws-sdk-go-v2
chmod -R +w /tmp/dlp-bench/corpus-d
# Verify SHA-256: 6cb2ec291e8335b7b4cb4b2bdabf473db697e11c92f92f5a9c6c6988d493d95a

# --- Wall-clock comparison, n=20 each, exports raw samples ---
CORPUS=/tmp/dlp-bench/corpus-b   # or corpus-d
hyperfine --warmup 3 --runs 20 --ignore-failure \
  --export-json /tmp/bench.json \
  -n pleno-dlp  "pleno-dlp scan filesystem $CORPUS --quiet --format json > /dev/null" \
  -n trufflehog "trufflehog filesystem $CORPUS --no-verification --no-update --json --log-level=-1 > /dev/null" \
  -n gitleaks   "gitleaks dir $CORPUS --no-banner --report-path=/dev/null --redact 2>/dev/null"

# --- Statistics from the JSON: median + bootstrap 95 % CI,
#     Welch's t, Cohen's d, Bonferroni-corrected p ---
python3 <<'PY'
import json, math, random, statistics
random.seed(42)

def boot_ci(xs, stat=statistics.median, B=10000, alpha=0.05):
    n = len(xs)
    bs = sorted(stat(random.choices(xs, k=n)) for _ in range(B))
    return bs[int(B*alpha/2)], bs[int(B*(1-alpha/2))]

def welch_t(a, b):
    ma, mb = statistics.mean(a), statistics.mean(b)
    va, vb = statistics.variance(a), statistics.variance(b)
    na, nb = len(a), len(b)
    t = (ma - mb) / math.sqrt(va/na + vb/nb)
    df = (va/na + vb/nb)**2 / ((va/na)**2/(na-1) + (vb/nb)**2/(nb-1))
    return t, df

def cohen_d(a, b):
    na, nb = len(a), len(b)
    va, vb = statistics.variance(a), statistics.variance(b)
    sp = math.sqrt(((na-1)*va + (nb-1)*vb) / (na+nb-2))
    return (statistics.mean(a) - statistics.mean(b)) / sp

d = json.load(open("/tmp/bench.json"))
rows = {r["command"]: r["times"] for r in d["results"]}
for name, xs in rows.items():
    lo, hi = boot_ci(xs)
    print(f"{name:12s} median={statistics.median(xs)*1000:7.1f} ms  "
          f"95% CI=[{lo*1000:6.1f}, {hi*1000:6.1f}]  n={len(xs)}")
for a, b in [("pleno-dlp","trufflehog"),
             ("pleno-dlp","gitleaks"),
             ("trufflehog","gitleaks")]:
    t, df = welch_t(rows[a], rows[b])
    p_two = math.erfc(abs(t)/math.sqrt(2))     # df>=20 normal approx
    p_bonf = min(1.0, p_two * 3)
    print(f"{a} vs {b}: t={t:.2f} df={df:.1f}  p_bonf~{p_bonf:.2e}  "
          f"d={cohen_d(rows[a], rows[b]):.2f}")
PY
```
