Secret scanning that closes the loop.

pleno-dlp detects 600 types of leaked credentials and PII, verifies them against the issuing provider, and can revoke the ones that are real. A single Go binary for filesystem, git history, stdin, and seven SaaS sources. No agent, no SaaS backend, no telemetry.

why pleno-dlp

Verification is the product

A regex match is a candidate. A finding is a credential the provider just confirmed. 550 of 600 detectors call the live API — on by default — and severity reflects it: verified means Critical, not "please triage." The remaining 50 are classified and audited in CI, not silently unverified.

Revocation closes the loop

Detection without response is a dashboard. pleno-dlp revoke invalidates confirmed leaks for GitHub, GitLab, Slack, AWS, and Stripe restricted keys — behind three explicit safety gates, and only ever against verified findings.

Signal, not noise

Documentation keys, fixtures, and placeholders are suppressed before they reach you. Every finding carries a stable secret_hash for dedup across runs, and allowlists handle the org-specific rest. PII detection is one flag away, in the same pass, on the same engine.

the loop

Detect across every surface secrets actually leak to — not just code.

pleno-dlp scan filesystem ./repo
pleno-dlp scan git --repo ./repo --branch main --max-depth 500
git diff | pleno-dlp scan stdin --label git-diff
pleno-dlp scan github --org acme
# also: gitlab, bitbucket, slack, notion, confluence, jira

Verify against the issuing provider. No flag needed — it is the default. Query the coverage at runtime instead of trusting a README:

pleno-dlp detectors list --verify-status

Revoke what is confirmed real. Irreversible, so it refuses to run without --confirm or --dry-run, and CI additionally requires PLENO_DLP_ALLOW_REVOKE=1.

echo "$LEAKED_TOKEN" | pleno-dlp revoke --detector github --secret - --confirm
pleno-dlp scan git --repo . --revoke-on-verified --revoke-dry-run

ci in three lines

Block leaks before they land. pleno-dlp protect scans only the staged, added lines of a commit — history noise can't fail your hook.

# .git/hooks/pre-commit
pleno-dlp protect

In CI, SARIF output plugs straight into GitHub Code Scanning, and --fail-on turns severity into exit codes:

- run: pleno-dlp scan filesystem . --format sarif > findings.sarif
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: findings.sarif

benchmarks

Median wall-clock over 20 runs (hyperfine, warm cache, verification disabled on all tools), 9.6 MiB corpus with zero secrets — the cold path every clean CI run pays. Apple M3, full methodology and corpus hashes published.

gitleaks 8.3023 ms[22, 23]5.2× faster

Yes, gitleaks is faster on this corpus — it ships ~160 regex rules with no verification or revocation; pleno-dlp dispatches 600 detectors. We publish the losses with the wins: raw samples, statistics, and threats to validity.

pii, same binary

Secrets are half of DLP. The other half — names, addresses, national IDs — is opt-in behind one flag, with a pluggable engine (pleno-anonymize or openai/privacy-filter). PII findings are tagged finding_class=pii so downstream tooling can route them separately from credentials.

pleno-dlp scan filesystem ./export --pii-engine=anonymize

built like it handles secrets

  • Raw secret values are never printed — output carries a SHA-256 secret_hash and a redacted prefix.
  • Releases are tag-driven with SLSA provenance and GitHub artifact attestation.
  • Verify-coverage classification is enforced by tests: a detector can't ship unverified without a documented reason.
  • Every test run passes the Go race detector. Race failures block merges.
  • AGPL-3.0. The scanner that reads your secrets should show you its source.
