# Private holdout set

The public corpus under `bench/fixtures/synthetic/` (generated) and the
public `leaky-repo` clone are both, by definition, things a competitor
(or a future pleno-dlp change chasing this specific benchmark rather
than general recall) can see and tune against. A holdout set that never
ships publicly is the check against that: numbers that only move because
the *public* corpus was memorized will diverge from the holdout: numbers
that hold on both did not come from overfitting the public one.

## Why nothing under `bench/` is the holdout

Anything committed to this repository — or even generated by a script
that *is* committed, if the script's output is deterministic — is
reconstructable by anyone with the repo, which defeats the purpose. The
holdout therefore cannot be scaffolding this PR ships as data; it can
only be a *mechanism* plus a documented convention for where a
maintainer keeps the actual content.

## Mechanism (already supported, no extra code)

`bench/harness`'s corpus flags are not hardcoded to the generated
public corpus path — point them anywhere:

```sh
go run ./bench/harness \
  -synthetic-dir /path/to/private/holdout/fixtures \
  -labels        /path/to/private/holdout/labels.json \
  -skip-leaky-repo \
  -out           /path/to/private/holdout/results
```

`labels.json` must match `bench/labels.Entry`'s schema
(`slug`, `file`, `pleno_dlp_detector`, optional `known_miss`) — the same
shape `bench/gen` writes for the public corpus, so the harness's
recall-scoring code (`bench/harness/recall.go`) needs no holdout-specific
branch.

## Where a maintainer keeps it

- A private repository (e.g. `plenoai/pleno-dlp-bench-holdout`, access
  restricted to maintainers) cloned locally, outside this checkout.
- Or a local-only directory never added to git — e.g. under
  `~/.dlp-bench-holdout/` — populated by hand from redacted incident
  fixtures or extra credential formats not (yet) worth publicizing.

Either way: **never** create this content under `bench/` in this
repository, and never add real secrets to it even privately — a holdout
fixture should follow the exact same rule as the public corpus (format-
valid *synthetic* credentials, or safely-expired/rotated real-world
samples with provenance you can stand behind), just not published.

## Status

This PR ships the mechanism and this document, not a populated holdout
— there is no existing private holdout content to relocate (the search
for prior fixture/benchmark code, per issue #298, turned up
`docs/comparison.md` and `docs/benchmarks.md`'s reproduction recipes only,
both already public). Populating one is a maintainer task, tracked
separately from this PR.
